# 已知问题与验证边界（v1.1.7-dev）

本文区分仍存在的产品限制与已修复的历史问题。源码与安全验收记录见 `VERIFY.md`、`CHANGELOG.md`。

## 当前限制

### 1. UWP / 商店应用可能无法自动重开

部分 UWP 应用无法取得 AUMID。结果窗的“重开刚才关掉的程序”会把它们列为需要手动打开；能够解析到可执行文件路径的传统桌面程序可按路径尝试重开。

### 2. 受保护进程可能无法结束

受保护进程或拒绝管理员操作的进程可能仍显示为“未结束”。工具会记录失败，不应把计划列表当成每个目标都能关闭的保证。

### 3. 未配置的 Session 0 服务不在进程清单内

候选进程来自当前交互式会话。Session 0 服务需用服务名配置在 `keep.json` 的 `services` 项中，才会由服务路径单独停止；`graceful` 只适用于进程优雅关闭。

### 4. 网络自检不修复所有虚拟网卡路由

程序可检测失效本地代理和部分回环 DNS 情况，但不清理 TAP/Wintun 等虚拟网卡遗留的悬空默认路由。遇到此情况需由对应 VPN/加速器正常恢复网络设置。

### 5. 清理性能缺少真实运行测量

本次只完成安全 dry-run、代码级检查和合成 UI 预览；没有执行真实清理。因此真实路径的 p50/p95、三秒预算触发比例、设备间收益与清理结果正确性都未实测。`docs/VERIFY.md` 中的 dry-run 时长不能代替真实清理耗时。

### 6. DPI 设备覆盖范围有限

交付截图在 150%（windowDpi=144）显示器生成。100% 与 200% 的实际显示器尚未验证，不能据此声称所有 DPI 组合均通过。

### 8. 自动化覆盖不完整

离线回归覆盖规则匹配、配置写入、撤销和 PID 复用判断。白名单联测使用合成进程与临时配置。提权链路、系统网络变化和真实进程生命周期仍需要现场验收。

## 已修复的历史问题

- 配置读取或校验失败会停止扫描、预演和清理。可用 `--check-config` 单独核对失败原因。
- 白名单区分进程名全等与路径子串；清理前会核对进程名和创建时间，避免 PID 复用误杀。
- 子进程调用使用系统目录完整路径；`kill.log` 采用追加写，并在超过阈值时保留完整的最近日志段。
- GPU 查询采用异步读取和超时；预演截图、进度采样、网络检测和 UI 消息泵已针对阻塞点调整。
- 自动关闭与 `--assume-dragged` 已移除，结果窗保留到用户手动关闭。
- 旧的深色主题分支、死的缩放函数、重复字体分配及未释放绘图资源已清理。
